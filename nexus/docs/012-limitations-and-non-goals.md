# Docs 012 - Limitations and Non-Goals

This document describes the intentional limitations of Nexus and what it explicitly does not attempt to do.

These boundaries are critical to understanding Nexus’s design and to using it responsibly.

---

## Not a Fully Autonomous System

Nexus is **not** designed to operate without human oversight.

It will not:

- Execute major decisions without user approval
- Continue indefinitely without checkpoints
- Assume intent beyond what is explicitly stated

Human judgment remains essential.

---

## No Persistent AI Memory

Nexus does **not** preserve ChatGPT conversations.

Specifically:

- Session history is not saved
- Context is not automatically accumulated
- AI agents do not “remember” past work

Only curated notes and decisions persist.

---

## No Guarantee of Correctness

Nexus cannot guarantee:

- Correct designs
- Bug-free code
- Optimal decisions

AI sessions provide suggestions and reasoning, not ground truth.

The user is responsible for validation.

---

## Not a Replacement for Engineers

Nexus does not replace:

- Software engineers
- Architects
- Product managers

It is a **coordination and amplification tool**, not a substitute for expertise.

---

## No Hidden Background Execution

Nexus does not:

- Run tasks silently
- Perform actions without visibility
- Execute destructive steps without confirmation

All meaningful actions are observable and governed.

---

## Not a General Autonomous Agent Platform

While extensible, Nexus is **not**:

- A marketplace of agents
- A self-evolving agent swarm
- A long-lived autonomous intelligence

Its focus is structured, goal-driven work.

---

## No Implicit Scope Expansion

Nexus does not:

- Add new goals automatically
- Expand project scope without approval
- Infer intent from partial input

Scope changes are explicit and deliberate.

---

## No Cloud Dependency

Nexus does not:

- Require external services
- Sync data to the cloud
- Depend on proprietary backends

All state is local and user-controlled.

---

## Limited by Model Capabilities

Nexus is constrained by:

- The reasoning ability of underlying models
- Context limits
- Latency and cost considerations

Nexus mitigates these limits through structure, not magic.

---

## MVP Constraints

In its MVP form, Nexus may lack:

- Advanced visualization
- Fine-grained customization
- Extensive plugin systems

These are potential future enhancements, not current guarantees.

---

## Summary

Nexus is intentionally constrained.

Its design prioritizes:

- Control over autonomy
- Explicit state over hidden memory
- Governance over speed
- Trust over convenience

Understanding these limitations is key to using Nexus effectively.
